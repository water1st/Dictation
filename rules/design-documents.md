# Design and Requirements Document Rules

> 此文件适用于 Dictation 的正式需求、设计、架构和领域文档。每次仓库文件修改须先有正式 Task 和用户授权。讨论、资料检查、审计与未定计划不因其存在而自动创建 Task。

## Elicit Requirements Before Writing

- 先阅读现有相关文档、代码、规格和领域术语。可以通过工具核实的客观事实由 AI 自行核实，不用问用户。
- 待决设计选择使用 `.agents/skills/grilling/SKILL.md` 分轮审问；涉及领域术语/重大设计时使用 `.agents/skills/grill-with-docs/SKILL.md` 与 `domain-modeling`。每轮提出有先决条件的问题与推荐方案，确认后继续下一轮。
- 思考、例子、原因、类比、假设、个人偏好及讨论材料不是默认获批准的设计。不得自行填补未定义字段、机制、条件、数值或功能。
- 用户批准最终方案后，按 `rules/project-management.md` 判断是否建 Task、是否同步到 `需求池`、何时进入执行；Skill 不授权直接修改文件或自行创建任务。

## Final State, Not Conversation

- **理解指令的意图后修改对应的正式定义，而不是替用户换句话写在文档中。**
- 文档正文只说明当前生效的设计、结构、字段、规则、公式和行为，确保不读聊天记录也能独立实现。
- 用户交代的前因后果、修改动机、被否决的选项、故事、疑虑、讨论过程、提示词、AI 推理、修改步骤，不自动写入正式文档。
- 某设定被替代时直接呈现最终状态，如 `系统使用 B。`，不得写成 `以前使用 A，现在不再使用 A，改为 B。`、`从 A 迁移到 B` 或相邻/分散的新旧对照。旧设定、旧术语、旧引用必须从受影响章节彻底删除。
- 有效的**当前**禁止性约束可保留；用户明确批准必须列入设计的前提或依据可记录。禁止的是无业务价值的历史否定留痕。
- 不在正式正文追加“本次修改说明”“根据用户要求”“AI 调整原因”或对话摘录；变更历史在 Git Commit、PR 和 Task 记录中追踪。
- 有明确理由且符合用途时才建 ADR；领域术语仅在真实改变时更新 CONTEXT.md，不能建立空白文档凑结构。

## Integrity and Scope

- 改动只涉及 Task 的实际目标和保持一致所必须修改的关联引用，不顺便重排或美化无关章节。
- 保留未被批准改变的字段、名字、单位、数值、公式方向、范围、条件、约束、主外键、数据所有权、状态和业务关系。
- 删除失效内容前确认现行仍有用的信息已保留；同步检查同名定义、上下游影响、内部引用和索引。
- 既有正式术语保持一致。纠正命名应语义识别受影响范围，不做盲目的整文件替换。
- 不把草案、样例、未来设想转成当前强制实现，不能用“常见做法”自行补全需求。
- 外部事实须区分已核验事实、假设和可能随时间变化的数据。冲突确实影响正确修改时，先查明权威来源或请用户决定。

## Document Version

- 文档版本与 Program Version 独立。既有文档仅首行已声明 `Doc Version` 者，以及 Task 明确指定为正式文档的新文件，适用 Document Version。
- 新正式文档默认首行为 `Doc Version: v 0.01`（Task 指定其他起始版本时除外）；普通笔记和不声明文档版本的文件不套用版本。
- 修改正式文档时，以本 Task 分支修改前的实际首行版本作为 base；一个独立交付 Task 将最低数位递增一次，记录 base/target；父子组对同一文档只递增一次，后续子项复用目标版本。
- `AGENTS.md`、`rules/*.md`、`.agents/skills/**` 是执行规范，不采用正式设计文档编号，也不会单独触发 Program Version 递增。

## Verification Gate

- 检查最终文档仅包含批准的现行定义；没有用户原话的重述、修改理由、对话过程或新旧设定留痕。
- 检查语义、段落、术语、数字、字段、关系、引用、版本、文档结构及实际 Git Diff。
- 机械检索仅辅助定位，不能替代语义审计；不能因关键词消失便宣称旧机制已彻底删除。
- 不能把文档长度、格式统一度、修改数量当成完成标准；必须验证目标正确、范围正确、信息完整。
