# C# Code Style Rules

> 适用于开发者手写的 Dictation C# 源码；代码生成器输出按框架自身约束管理。

## Names and Files

- 类型、接口以 PascalCase 命名；接口名前缀 I；方法、属性、事件名称使用 PascalCase。局部变量和私有字段按现有 camelCase 约定；常量按有意义的标准 C# 命名。
### English-Only Names for Classes, Methods, Variables, and Other Code Elements

- **项目自行定义的类名、结构体名、接口名、枚举类型名、枚举成员名、记录类型名、委托名、类型别名、命名空间各段名称、泛型类型参数名、事件名、属性名、字段名、常量名、变量名、函数名、方法名、局部函数名、扩展方法名、方法参数名、Lambda 参数名及具名元组元素名，全部必须使用英文。** 只使用有意义的英语单词或通行英文缩写，禁止汉字、其他非 ASCII 字母以及用中文拼音替代英文命名；同时遵守上方的 C# PascalCase、camelCase 等约定。
- 上述各类名称的首字符只能是 ASCII 英文字母（`A-Z`、`a-z`）或 C# 命名规则允许的下划线（`_`）；后续字符只能是 ASCII 英文字母、数字（`0-9`）或下划线，不能以数字开头。**每个完整名称必须匹配正则表达式 `^[A-Za-z_][A-Za-z0-9_]*$`。** 命名空间或带命名空间的类型名应逐段检查，不把分隔各段的 `.` 当作名称字符。
- **单元测试、集成测试及自动化测试同样强制执行**：测试类名、测试夹具类名、测试函数名/方法名、测试参数名、测试变量名、测试字段名、辅助类名、辅助函数名/方法名及其他项目自行定义的名称，均按上述要求使用英文，不得以中文命名。该要求覆盖全部 `Dictation.*` 自有项目，包括 XAML 中通过 `x:Class`、`x:Name` 或 `Name` 定义的类名、控件变量名。
- **中文注释不受英文代码命名规则限制，而且必须继续遵守本文件已有的中文注释要求。** 普通代码注释、`//` 注释、`/* ... */` 注释、`///` XML 文档注释及其说明内容可以并应按既有要求使用中文；不能将“代码名称必须使用英文”解释成“注释必须使用英文”，也不得为执行本规则翻译已有中文注释。字符串字面量、中文异常消息、测试数据、界面显示文字、本地化资源内容与普通说明文档也不在英文代码命名限制内。
- 使用 .NET、第三方库或外部协议已定义的 API 名称时，保持其约定拼写；本规则约束项目自行定义的代码名称，不要求修改外部 API 的名称。

- **每个手写类型独立一个同名 .cs 文件**，包括 class、interface、struct、enum、record 和 delegate，即使类型只占数行代码。禁止在一个源文件声明多个手写类型、通过私有嵌套辅助类型规避或以节省文件数为理由合并。
- XAML、资源字典以及其他项目文本文件可以直接编辑；必要的 partial 类型可跨文件声明，但一个手写文件不得捆绑其他类型。
- 使用 4 空格缩进、Allman 大括号、传统块级 namespace，启用可空引用，正确处理 null。
- **禁止 Primary Constructors 和 Top-Level Statements**。每个程序入口显式 `Program.Main`，WPF 遵从其应用入口和 STA 要求。构造函数显式声明，依赖存储在明确定义的 readonly 字段，逐项赋值。
- 反对为缩短行数而使用复杂表达式体、隐式/位置参数生成成员、难以阅读的嵌套三元表达式和复杂链式语法；合理简单语法不做无依据的全面禁用。

## Abstractions

- 能产生明确能力划分、访问权限隔离、跨程序集合同、扩展/替换或测试隔离价值时使用接口；实现只有一个也可有价值。
- 不机械生成 `IXxx + Xxx`；无真实抽象需求的内部类直接注入具体类型。
- 调用方只依赖自己需要的能力接口，一个实现可以提供多个小接口；必要时组合接口。
- 优先内部实现、最小可见性；跨程序集合同、DTO、XAML 需要的类型按需要公开。不要为了单元测试擅自扩大公共 API。
- 首选组合/DI，不建立没有真实关系的继承层次、泛用 Repository、CQRS、DDD 或无用框架。

## Immutability, Dependencies and Clarity

- 编译期常量使用 const；运行时构造后不变的实例字段使用 readonly。避免可随意修改的共享状态。
- 先用 .NET BCL、Microsoft.Extensions 和已有依赖，其次选择成熟、维护良好、轻量且许可证兼容的第三方包；最后才实现必要的最小缺口。不重写成熟库已有的核心功能。
- 避免反射扫描、运行时生成/编译代码和不确定的动态分派。优先显式注册、强类型字典、工厂、普通泛型与受控解析器；仅在有明确可核验需求时使用较动态机制。
- XML 职责注释用简明中文，公开合同和有实际复杂性的行为说明参数、边界与原因；不把显然的代码逐行转写成注释。
