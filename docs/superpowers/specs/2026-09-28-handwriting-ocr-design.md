# 手写输入、离线 OCR 与人工复核设计

**状态：** 待用户复核；本规格不授权 OCR 实现或开发环境安装。

**范围：** 日语、英语学习与复习的手写答题，以及后续错题复核。保留现有键盘答题、单窗口导航、Core 业务层和用户数据目录边界。

## 目标与边界

日语默认手写、英语默认键盘；每种语言可独立设置默认方式，每题可临时切换。手写答案由本地 CPU OCR 识别，再经现有答案规则判定，不采用“熟悉／陌生”等主观评分。误把错误答案判为正确的代价高，因此识别不确定时宁可暂缓判题，也不能猜测后计入学习进度。输入、识别、复核都留在唯一 WPF 窗口内；不得上传笔迹或在线调用 OCR。

本次不增加词形、复习算法或额外窗口，不以 OCR 替代英语键盘模式。音频仍只在内存中播放；保留笔迹是为了申诉，不意味着保存语音文件。

## 输入与页面行为

Presentation 使用 WPF `InkCanvas` 接收鼠标、触控笔和触摸。初始只显示一个空书写格；用户在末格书写后再补一个空格，不按答案字符数预先生成格子。允许擦除、清空与重新书写；识别时把格内笔迹合成连续行图像，避免引入整页文字检测模型。日语格子可切换半透明米字格；格线仅在 UI 背景显示，不进入送给 OCR 的图像。每题切换输入方式不改变当前题、计数或预期答案。

英语键盘 `TextBox` 禁用拼写检查、自动补全与自动纠错。手写和键盘最终都交给 Core 的同一答案规范化／判定规则；Presentation 不自行判断对错。未提交前不在题面、输入提示或识别候选中展示目标答案。

## 离线识别与可信度

提供一个小的 `IHandwritingRecognizer` 能力接口：输入内存图像、语言及取消令牌，返回识别文本、候选、置信信息和模型版本。WPF 只负责笔迹采集与图像适配；Core 负责识别结果是否可用于自动判题、答案比较和状态变更；DataAccess 只负责证据及结果持久化。具体本地 Provider 在组合根注册，不创建第二套业务容器。Windows Ink 的系统识别器仅在相应语言识别包可用时作为辅助证据，不能成为部署前提；PP-OCRv5 是离线主路径。

原始 `Resources/PP-OCRv5_server_rec_infer.tar` 是 Paddle 静态推理格式，不能直接当作 ONNX 文件。优先在构建阶段验证官方 PaddleX/Paddle2ONNX 转换、预处理、字符表和解码与原模型的一致性，运行时复用现有 ONNX Runtime CPU 能力；若转换或对照样本不通过，停止 OCR 实施方案复核，不在用户机器上偷偷安装 Python/Paddle，也不静默改用未经批准的模型。[PaddleOCR 官方转换说明](https://www.paddleocr.ai/v3.1.1/en/version3.x/deployment/obtaining_onnx_models.html)明确转换需独立工具链；发布包只带核验后的运行模型、配置、许可证和归属。

自动判定门槛从实际日语假名／汉字与英语手写样本校准，分别记录误判为正确、误判为错误和弃权率；不照搬模型公开基准或臆设固定阈值。[PaddleOCR 模型说明](https://www.paddleocr.ai/main/en/version3.x/module_usage/text_recognition.html)表明 PP-OCRv5 支持日英及手写，但该通用数据集成绩不能代表本产品笔迹的判题准确率。只有结果清晰且满足经实测确定的门槛时才自动判题；低置信、识别器冲突、空白或异常均不计对错、不推进题目，先提示重写。仍无法确认时进入待人工复核，不在提交前列出可能泄露答案的候选。

## 证据、申诉与状态一致性

提交时保存版本化的原始笔迹、识别器候选与置信诊断、自动判定、题目和模型版本到根目录 `DATA/UserData.db`。仅保存核对所需证据，限制大小；不保存每次渲染的临时图像。低置信提交与已判错申诉在同一人工复核入口管理：List 给出批量概览，Detail 展示题面、正确答案、笔迹、OCR 诊断及对应发音按钮。复核入口沿用单窗口 `ContentControl + UserControl` 导航和返回状态。

人工覆盖不改写原 OCR 证据；另记人工结果与时间，生效判定取人工结果优先。Core 对受影响词形按有序答题记录重新计算连续正确、错题、学习完成及将来的复习/FSRS 状态；DataAccess 在一个事务内保存覆盖与重算结果。重算不应凭当前计数增减来猜测历史，也不得重复计入每日组数。进行中的题目如受覆盖影响，要安全重取待答题而非保留过期状态；整组删除仍级联删除相关笔迹、诊断、复核与进度。

## 验证出口

实施计划须先证明：原始模型可转换且 CPU 本地推理与基准输出一致；真实笔迹样本可覆盖日语假名／汉字、英语大小写、空白、多格、改写和难辨字符；错误自动放行的风险、耗时与内存占用可量化。随后用可编译的行为 RED→GREEN 测试覆盖输入切换、弃权不推进、正确／错误、异常、取消、证据保存、人工覆盖及重算；再跑全量测试、单窗口真实 UI 冒烟和无网络／无音频文件检查。若准确率门槛无法满足，保留键盘输入和人工核对，不宣称 OCR 已可靠完成。
